# RWKV 代码审查

输出可操作的代码审查结果。以项目已有约定和代码行为为依据；不要把个人风格偏好当成缺陷。

## 流程

1. 阅读适用的 `AGENTS.md` 和项目贡献说明。确认用户指定的仓库、PR 或比较范围；保留现有未提交改动。
2. 用户指定 PR 或提交范围时使用该范围；只有用户要求审查当前未提交改动时才审查工作区和暂存区。没有明确范围且多个范围都合理时，简短询问。不要擅自选主分支或上一个提交。
3. 先查看 Git 状态、改动列表和 diff，再读取必要的调用方、数据结构及邻近代码。搜索时优先使用 `rg`。
4. 追踪具体输入、条件和结果，检查错误处理、数据边界、访问控制、并发、持久化及接口兼容性。只报告能解释触发条件和实际影响的问题。
5. 有现成且必要的验证方法时，按项目要求执行有针对性的检查。区分实际执行的检查与静态推断，说明覆盖限制；不要声称未执行的测试通过。
6. 按严重性排序。每条包含简短标题、文件及行号、触发条件、影响和修复方向。不要把大段 diff 复制进回复。

## 输出

- 首先列出发现的问题；高优先级表示会导致数据损失、权限绕过、核心流程失败或类似具体影响，不能仅因代码复杂就提高级别。
- 接着列出尚需确认的假设和验证情况。
- 没有发现可证实的问题时明确说明，并说明未覆盖的范围，避免保证绝无问题。
- 仅在用户要求修复时修改代码；仅在用户明确要求向他人发布时提交远程评论。

示例：`$rwkv-code-review 审查当前暂存区改动，重点关注登录权限和数据写入。`
